# dsh-offpeak-inbox 需求规格

> 状态：**v0.1 已在本机实现并验证**；本文档是面向开源发布的 **v0.2 需求指令**（含保留项与新补项），不改变已实现的既有契约。
> 读者：插件使用者、后续施工的 Agent、外部贡献者。

## 1. 一句话定位

平时把想法、待办、整段对话攒进收件箱；**只在 DeepSeek API 平价（错峰）时段**由 Host 自动新建 DSH 会话去执行，把高峰时段的价格差省下来。

## 2. 问题与目标

| | 内容 |
|---|---|
| 真实问题 | 高峰时段单价约为平价的两倍；用户遇到值得做的事时，常常"不急、但不想现在花钱做" |
| 现有作法的缺陷 | 靠人记性等到便宜时段再手动发起，必然忘；客户端定时器（关页面即失效）不成立 |
| 目标 | 捕获与执行解耦：捕获随时可做，执行由 Host 按时钟自动完成，且**漏掉的窗口不浪费额度、不丢条目** |
| 成功判据 | 用户记一条 → 关掉电脑/离开 → 下一个平价窗口开着 Host 时，条目自动变成一个有结果的会话，且会话可追溯 |

## 3. 非目标（明确不做）

1. 不做"唤醒睡眠机器"的保活；Host 不在运行就不执行（已有 keep-awake 类插件负责此事，职责分离）。
2. 不做余额/计费展示（市场已有十余款同类插件，本插件只做"错峰执行"这一件事）。
3. 不做高峰拦截（那是 dsh-peak-block 的职责）；本插件不干预用户的即时请求。
4. 不改动 DSH 主循环与既有扩展点语义；全部行为挂在文档化的扩展点上。

## 4. 用户故事

| 编号 | 故事 | 对应能力 |
|---|---|---|
| US-1 | 我 10 点想到一个重构任务但不想现在花钱，记一条，晚上自动跑 | 捕获 + 计划 + 自动执行 |
| US-2 | 我半夜 2 点（平价时段）记一条，希望它立刻跑，而不是等到明天 | 窗口内捕获即入当前窗口 |
| US-3 | 我想知道现在是贵还是便宜、下一个便宜窗口几点开始 | 面板状态区 |
| US-4 | 我记完就想马上跑，不等窗口 | 立即执行 |
| US-5 | 某条跑失败了，我改一下再放回队列 | 编辑 + 重试 |
| US-6 | 我要看到这条变成了哪个会话、结果在哪 | 会话标题前缀 + 状态区会话入口 |
| US-7 | 我不想让 AI 误以为收件箱里的文字是"系统指令" | 下发文本带来源说明与"这是数据"边界 |
| US-8 | 我想按自己的时区/自己的峰谷口径算 | timeZone + ranges 可配 |

## 5. 功能需求

### A 组：捕获与计划（v0.1 已实现，v0.2 保留）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-1 | 侧边栏「错峰收件箱」入口；支持标题（可选）+ 正文（必填） | 正文为空时拒绝提交；提交后条目立即出现在列表且已落盘 |
| FR-2 | 捕获即定计划：算出"最早可执行时刻" | 平价窗口内捕获 → 计划时刻为当前窗口起点；高峰或间隙捕获 → 计划时刻为下一个平价窗口起点 |
| FR-3 | 到点自动新建真实会话并下发条目原文 | 新建会话、标题为 `[错峰] <标题或正文前 40 字>`、提示词含捕获时间与"以下是用户记下的数据"边界说明 |
| FR-4 | 状态可见：等待错峰 / 执行中 / 已完成 / 失败 | 面板与 Host 快照一致；状态迁移只经状态机 |
| FR-5 | 条目操作：编辑、删除、立即执行、失败重试 | 运行中的条目不可编辑/删除；仅失败或已取消可重试 |
| FR-6 | 面板显示当前峰谷判定、当前窗口起止、下一窗口开始时间 | 由 Host 计算并通过 SSE 推送，浏览器不自行推算 |
| FR-7 | 总开关 + 向 agent 声明插件存在（可关） | 关掉总开关后只收不跑；关掉声明后系统提示不再注入该段落 |

### B 组：调度与结算（v0.1 已实现，v0.2 保留）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-8 | 调度心跳：按 `launchIntervalSeconds` 轮询，窗口开着且有到期条目才动作 | 非窗口期不产生任何会话；下限 2 秒防止空转；旧名 `tickSeconds` 仍被接受 |
| FR-9 | 削峰：单轮最多启动一条，积压跨轮次淌出 | 同一 tick 内不会同时创建多个会话 |
| FR-10 | 执行结算：区分"还在跑"与"已结束"，且**读不到名册时绝不误判完成** | 双通道判定（进程内 agent 状态优先，会话名册兜底）；名册读取失败时不结算 |
| FR-11 | 超时保护：超过 `executionTimeoutSeconds` 未结束则标记失败并提示查看会话 | 失败原因文本含分钟数与"请查看该会话" |
| FR-12 | 持久化与损坏隔离 | 写入为原子替换；文件不可解析时改名保留现场，调度器以空账本启动并在控制台报错 |

### C 组：开源版待补（v0.2 计划）

按优先级排序；P0 = 开源发布前应有，P1 = 首个公开版本后尽快，P2 = 观察需求后再做。

| 编号 | 需求 | 优先级 | 理由 / 验收标准 |
|---|---|---|---|
| FR-13 | **取消**一条执行中的条目 | P0 | 状态机已有 `cancelled`，但当前没有任何入口能进入该状态——这是一个已存在但够不着的状态位。验收：面板可取消；取消后条目可重试；正在跑的会话不被强杀（只解除收件箱的跟踪） |
| FR-14 | 每条目可选执行身份（模型 / 推理强度 / agent preset） | P0 | 错峰省钱的完整逻辑是"贵的模型放到便宜时段跑"；当前所有条目按默认身份执行，省的一半价值被削掉 |
| FR-15 | 并发上限可配（默认 1） | P0 | 当前"每轮 1 条"写死在调度器里，不是配置项；积压 20 条时会排到天亮 |
| FR-16 | 每条目可选执行工作区 | P1 | 不同条目属于不同项目；缺省用 Host 当前默认工作区 |
| FR-17 | 错峰窗口策略可配：`strict`（默认，不补跑）/ `catchUp`（补跑错过窗口） | P1 | 单机用户常希望"电脑刚开机就把攒的跑掉" |
| FR-18 | 完成通知（桌面通知 / Webhook / 复用已有推送渠道） | P1 | 结果要回看才知道，等于没跑完；依赖方是通知类插件，需可降级 |
| FR-19 | 一键把"当前这段对话"攒进收件箱 | P1 | 捕获面从"打字"扩展到"会话残留任务"；正文带会话引用 |
| FR-20 | 失败自动重试（次数与退避可配，默认关闭） | P2 | 网络类失败常见，但默认替用户花额度需谨慎 |
| FR-21 | 条目分组 / 标签 / 搜索 | P2 | 条目超过几十条后列表不可用 |
| FR-22 | 双语界面（中/英）+ 英文 README | P0 | 开源可见性的硬前提；客户端文案需走本地化字典而不是散落的字符串 |
| FR-23 | 窗口开启时的"批量预热" | P2 | 在并发上限内一次填满，减少空等窗口的空转 |

## 6. 非功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-1 | Host 半区运行时依赖为零 | 所有 harness 服务通过注入获得；不 import harness 包作为运行时值。新增能力不得引入运行时依赖（schema 校验、路由、持久化均自实现） |
| NFR-2 | 断电容错 | 落盘为"临时文件 + 改名"；进程崩溃不得留下半截 JSON；不得静默丢条目 |
| NFR-3 | 安全边界 | HTTP 接口只服务回环地址 + 同源标记 + 方法/内容类型校验 + 体积上限；任何非回环、跨源、非 JSON 的请求一律拒绝。这是"能创建真实会话"的接口，不得放宽 |
| NFR-4 | 无硬编码可调项 | 一切部署相关取值都是可校验的配置项；常量只留给协议常量与安全不变量 |
| NFR-5 | 跨平台 | Windows / macOS / Linux，Node ≥ 22；不得依赖平台专有 shell |
| NFR-6 | 测试 | 纯函数（日历）、状态机、调度决策、以及**针对构建产物**的真实运行时测试；CI 必须绿 |
| NFR-7 | 不打扰 | 空闲轮询不得占满 CPU；无到期条目时不产生会话、不产生日志噪音 |
| NFR-8 | 隐私 | 条目正文只落本机 `$DSH_HOME`，不经任何第三方；下发给模型时明确标注为"用户记下的数据" |
| NFR-9 | 可诊断 | 面板未出现时，能一眼区分"客户端脚本没跑"与"插不进 DOM"（已有计数式自证钩子，保留） |
| NFR-10 | 文档 | README（面向使用者）、配置表、数据位置、边界说明、故障排查；中英对照 |

## 7. 外部契约（向后兼容，不得随意破坏）

### 7.1 配置项

| 键 | 类型 | 默认 | 语义 |
|---|---|---|---|
| `enabled` | boolean | `true` | 总开关（只收不跑） |
| `timeZone` | IANA 字符串 | `UTC` | 峰谷区间按哪个时区解释 |
| `ranges` | `[{start,end}]` | 01:00–04:00、06:00–10:00 | 工作日高峰区间，`HH:MM`，左闭右开 |
| `announceToAgent` | boolean | `true` | 是否向 agent 声明本插件 |
| `launchIntervalSeconds` | 整数 ≥ 2 | `10` | 两次启动尝试之间的间隔。每轮最多启动一条会话，因此它决定积压排空的速度，而非每轮跑几条。旧名 `tickSeconds` 仍被接受 |
| `executionTimeoutSeconds` | 整数 ≥ 60 | `14400` | 单次执行超时 |

### 7.2 HTTP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/offpeak-inbox/state` | 返回全部条目 + 调度器视图 |
| POST | `/api/offpeak-inbox/action` | 动作：`create` / `update` / `remove` / `runNow` / `retry` / `clientLoaded` |
| GET | `/api/offpeak-inbox/events` | SSE 推送（含 15 秒心跳） |

### 7.3 数据文件

`$DSH_HOME/offpeak-inbox/inbox.json`：`schemaVersion`（当前 1）、`revision`、`items[]`、`scheduler`。
条目字段：`id`、`title`、`prompt`、`createdAt`、`runAfter`、`status`、`sessionId?`、`startedAt?`、`settledAt?`、`error?`。
**`schemaVersion` 变化必须提供迁移**，不允许直接丢弃旧账本。

### 7.4 消费的宿主服务

必需：`typertGateway`、`agents`、`webServer`、`systemPrompt`。
可选（缺了也要能启动）：`settings`、`now`（测试用时钟）。

## 8. 边界与已知限制（必须写进 README）

1. Host 不在运行就不执行；插件活在 `dsh web` 进程里。
2. 错过的窗口默认不补跑（改为 `catchUp` 后例外）——但条目的计划时刻在捕获时就已确定，所以条目不会丢。
3. 不唤醒睡眠的机器。
4. 执行消耗真实 API 额度，省的是差价不是免费。
5. 同一时刻默认只跑一条（并发上限放开后按配置）。

## 9. 验收口径（Definition of Done）

- [ ] `typecheck`、`build`、`test` 三条命令在干净检出上全绿（Linux 与 Windows）。
- [ ] 仓库内无本机绝对路径、无个人目录、无凭据。
- [ ] 全新机器上按 README 三步（安装 → 改配置 → 重启 dsh web）能跑通。
- [ ] C 组 P0 项全部落地并各有测试。
- [ ] 中英文 README 齐备，配置表与数据位置与实际一致。
- [ ] **已收录进 DSH 插件市场**（投稿一个 `data/plugins/<owner>__<repo>.yml`；条件与投稿包见 `docs/MARKET-LISTING.md`），且 Release 上的 tarball 链接实测可下载、资产名不带版本号。
- [ ] 至少一个真实场景的端到端记录：捕获 → 等窗口 → 自动开会话 → 条目结算为已完成。

## 10. 可直接下发的施工指令块

> 施工对象：本仓库（Cordis 插件，Host 半区 + 浏览器半区）。
> 任务：按本目录 `docs/REQUIREMENTS.md` 的 C 组 P0 项改造，并完成 `docs/OPEN-SOURCE-CHECKLIST.md` 的全部阻断项。
> 硬约束：
> 1. 保持 A/B 组既有行为与第 7 节外部契约向后兼容；
> 2. Host 半区不新增运行时依赖；浏览器半区保持零依赖；
> 3. 任何落盘改动都必须保留原子写与损坏隔离；任何接口改动都必须保留回环 + 同源守卫；
> 4. 每个新能力补测试，`test/runtime.test.ts` 针对构建产物运行，改 Host 代码后必须先构建再测；
> 5. 改完客户端半区必须重新包装并重启 `dsh web` 验证（客户端模块只在启动时读取一次）；
> 6. 不得提交 `lib/`、`node_modules/` 或任何本机路径。
> 交付：可运行的分支 + 更新后的文档 + 一份变更说明（哪些需求编号已满足、哪些延后及理由）。
